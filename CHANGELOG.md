# Changelog

## [1.10.0] - 2026-08-29

- В карточку сервера добавлен управляемый режим планового обслуживания с
  отдельным подтверждением запуска.
- При переходе в maintenance бот запоминает прежнюю настройку выдачи и
  временно исключает сервер из создания новых ключей, не удаляя существующие.
- Фоновый мониторинг не переводит обслуживаемый сервер в offline и не запускает
  ложный сценарий массовой замены ключей.
- Завершение обслуживания сначала проверяет VPN/API; при ошибке сервер остаётся
  в maintenance, а выдача не включается.
- После успешной проверки восстанавливается прежний режим выдачи, а завершение
  обслуживания появляется в журнале восстановлений центра состояния.
- Миграция v23 хранит состояние обслуживания отдельно и не изменяет ключи,
  платежи или пользовательские конфигурации.

## [1.9.0] - 2026-08-29

- Центр состояния сохраняет неизменяемый журнал реальных переходов между
  `ok`, `warning` и `error`; одинаковые повторные проверки не создают шум.
- На экране показано количество непросмотренных событий и до пяти последних
  восстановлений компонентов.
- Добавлена кнопка подтверждения просмотра событий. Она не скрывает активные
  проблемы и не меняет состояние VPN или серверов.
- История инцидентов хранит прежний и новый статус, безопасные подробности и
  время перехода, поэтому восстановление больше не стирает контекст ошибки.
- Обновление базы выполняется автоматической миграцией v22 без изменения
  существующих ключей, платежей и настроек.

## [1.8.0] - 2026-08-29

- Раздел «Операции» превращён в единый центр состояния: показывает активные
  ошибки и предупреждения VPN, панелей, сверки ключей, замен и резервных копий.
- Для каждого инцидента отображаются понятное имя компонента, безопасная
  диагностика и свежесть последней проверки.
- Из центра состояния можно сразу открыть карточки проблемных серверов.
- Кнопка «Проверить сейчас» запускает штатный мониторинг вручную и обновляет
  экран; проверка не удаляет ключи и не меняет настройки серверов.
- Параллельные ручной и фоновой проходы мониторинга сериализованы, поэтому они
  не выполняют одни и те же сетевые и резервные операции одновременно.
- Состояния мониторинга получили типизированную выборку и тесты сортировки
  инцидентов перед исправными компонентами.

## [1.7.0] - 2026-08-29

- Авторизация и безопасные GET-запросы к `amneziawg-panel` автоматически
  повторяются до трёх раз при сетевых сбоях и HTTP 5xx; создание ключа не
  повторяется, поэтому временная ошибка не приводит к дублям.
- Диагностика определяет сообщаемую панелью версию и фактический вариант JSON,
  показывает число клиентов и короткий отпечаток ответа.
- Неизвестные ответы больше не попадают в журнал целиком: сохраняются только
  размер, структура JSON и SHA-256-отпечаток без имён и ключевых данных.
- Карточка панельного сервера отдельно показывает состояние узла/API,
  совместимость формата API и свежесть статистики.
- Добавлена отдельная кнопка проверки API панели; полный тест выдачи по-прежнему
  проверяет создание, загрузку конфигурации и обязательное удаление ключа.

## [1.6.1] - 2026-08-29

- Доступность `amneziawg-panel` больше не зависит от успешного разбора списка
  клиентов: рабочая панель не помечается offline из-за изменившегося JSON.
- Декодер принимает прямой массив, обёртки `clients`, `data`, `result`, `items`
  и `rows`, вложенные ответы, UTF-8 BOM и числовые идентификаторы клиентов.
- Запрос панели явно отключает сжатие ответа и показывает Content-Type и
  безопасное начало неожиданного ответа для диагностики.
- Для панельных серверов больше не предлагается `transfer.sh bridge`: этот
  SSH-мост к HTTP API панели не относится.
- Мониторинг отдельно сообщает о доступной панели с несовместимым форматом,
  продолжая считать VPN рабочим и не отключая выдачу ключей.

## [1.6.0] - 2026-08-27

- Кнопка «Не подключается» запускает диагностику конкретного ключа и различает
  недоступный сервер, истёкший срок, отключение в панели, свежий handshake и
  отсутствие соединения с устройства.
- Добавлен пошаговый мастер: проверка сети, проверка приложения, повторная
  выдача существующего подключения и передача диагностики администратору.
- Инструкции разделены по Android, iPhone/iPad, Windows и macOS и открываются
  из карточки выбранного ключа.
- Пользователь может отправить безопасную автодиагностику в поддержку одной
  кнопкой; в обращение входят сервер, срок, состояние, handshake и трафик, но
  никогда не входят приватный ключ или содержимое конфигурации.
- Новые callback-действия включены в исчерпывающую проверку полномочий и тест
  всех кнопок интерфейса.

## [1.5.0] - 2026-08-27

- Карточка пользовательского ключа показывает AWG-сервер, фактическое
  состояние ключа в панели, последнее подключение, входящий и исходящий трафик
  и свежесть телеметрии.
- Кабинет ключей получил компактную активность и общий трафик для каждого
  подключения; отсутствие данных обозначается явно.
- Карточка сервера показывает загрузку относительно лимита, количество online
  и включённых ключей, суммарный трафик панели и время последнего опроса.
- Раздел серверов получил общую загрузку инфраструктуры и число подключённых
  сейчас пользователей.
- Добавлен единый слой runtime-статистики для AmneziaWG Panel и локального AWG
  с тестами handshake, трафика и устаревания online-состояния.

## [1.4.0] - 2026-08-27

- В админ-панель добавлен экран незавершённых операций замены: видны
  пользователь, старый и новый ключ, целевой сервер и возраст операции.
- Главные экраны администратора и пользователя показывают количество замен,
  ожидающих проверки, не создавая повторных ключей.
- Мониторинг предупреждает администратора о заменах без решения более суток и
  повторяет уведомление только при изменении набора проблемных операций.
- Добавлены проверки выборки незавершённых замен, пользовательских счётчиков и
  точной 24-часовой границы мониторинга.

## v1.1.0

- Логическое удаление ключей дополнено постоянным архивным журналом.

- Веб-кабинет получил скачивание конфигураций, QR-коды, историю платежей и

- Добавлен HMAC-SHA256 webhook-контур эквайринга с проверкой номера заявки,

## v1.0.0

  обновления, список изменений GitHub и явный вопрос перед установкой.

## [0.31.0] - 2026-08-26

- В карточке пользователя раздел «Ключи» стал управляющим: каждый ключ можно
  открыть или удалить после отдельного подтверждения. Удаление выполняется на
  фактическом AWG-сервере/панели и сразу скрывает ключ из кабинета и базы.
- Удаление уже отсутствующего на VPN-сервере ключа теперь считается успешной
  очисткой учёта, а не оставляет неудаляемую запись в интерфейсе.
- Исправлено продление Telegram Stars и ручное изменение срока для ключей
  удалённых AWG-панелей: операции больше не вызывают локальный VPN-скрипт.
- Техническое (legacy) продление восстановленных на панели ключей также
  маршрутизируется через их фактический сервер при оплате балансом или после
  одобрения банковского перевода.
- Исправлена пакетная генерация: она использует основной AWG-сервер, проверяет
  общий реестр имён, назначает каждому ключу сервер и откатывает частично
  настроенный ключ при ошибке срока или привязки.
- Синхронизация AWG-панели и изменение срока сохраняют локальный кэш expiry,
  поэтому кабинет показывает реальный срок, а продление учитывает остаток.
- Сводка админ-панели считает ключи по общему реестру всех серверов, а не
  только по локальному VPN-скрипту контроллера.

## [0.30.1] - 2026-08-26

- Исправлены зависшие замены, созданные версиями до 0.29.0: бот находит уже
  выпущенный новый ключ, скрывает старый, повторно отправляет конфигурацию и
  кнопки подтверждения/отката вместо создания очередного дубликата.
- Прямая или повторная команда замены также сначала проверяет pending-запись,
  поэтому параллельные нажатия не увеличивают количество ключей на панели.
- Повреждённая pending-запись без нового активного ключа автоматически
  закрывается, после чего допускается ровно одна чистая повторная попытка.

## [0.30.0] - 2026-08-26

- Одобрение заявки «Восстановить ключи» теперь создаёт ключ на рабочем
  сервере, назначенном кнопкой «Новые ключи и замена», включая AWG-панель;
  локальная команда на сервере Telegram-бота больше не используется.
- Заявка атомарно резервируется на время создания: повторные нажатия не могут
  выпустить несколько ключей. При ошибке панели резервирование снимается, а
  частично созданный ключ удаляется.
- В карточке старого сервера появилась адресная рассылка только владельцам его
  активных ключей с готовой подсказкой о самостоятельной безопасной замене.
- Подтверждённая замена оставляет в кабинете только новый ключ; старый остаётся
  в истории как архивный и не участвует в повторных заменах.

## [0.29.0] - 2026-08-26

- Старый нерабочий ключ скрывается сразу после успешного выпуска замены,
  поэтому повторный запуск восстановления не создаёт бесконечные дубликаты.
  Подтверждение оставляет новый ключ, а откат удаляет его и возвращает старый.
- Восстановлена покупка переводом из клиентского меню: выбор сервера больше не
  пропускается, заявка сохраняет сервер, чек (текст, фото или документ)
  пересылается администраторам, а после одобрения ключ выдаётся пользователю.
- Продление переводом теперь корректно меняет срок ключей на удалённых
  AWG-панелях, а не пытается выполнить локальную команду на сервере бота.
- Личный кабинет и список подключений получили единые статусы, понятные шаги
  покупки, сведения о сервере и явные инструкции по восстановлению и оплате.

## [0.28.0] - 2026-08-26

- Проверка старого сервера теперь сохраняет результат: если сервер недоступен,
  выдача на нём выключается, а все привязанные к нему активные ключи сразу
  отображаются пользователям как нерабочие и доступные для восстановления.
- Клиентский список показывает устройство, техническое имя ключа, сервер,
  понятный статус и срок действия; кнопки также содержат имя устройства и
  ключа, чтобы несколько подключений было легко различать.
- Для нерабочего ключа бот больше не пытается повторно выдать бесполезный файл
  старого сервера, а сразу объясняет процедуру безопасной замены.
- Подтверждённый старый ключ архивируется и скрывается из активной базы;
  отмена замены сохраняет старый ключ и удаляет только новый.

## [0.27.1] - 2026-08-26

- Аварийная замена разрешена только для ключей, исходный сервер которых
  недоступен, и всегда направляет ключ на другой рабочий основной сервер.

### 🇷🇺 Русский

#### ⚠️ Breaking

#### Добавлено

- 🛠 **Изменение параметров клиента** (`modify`): Keepalive, DNS, AllowedIPs,
  Endpoint — кнопка «⚙️ Изменить» в карточке клиента.

  `.conf`/`.png`/`.vpnuri` по имени — теперь всё из JSON-ответа скрипта.
- Деструктивные команды (`remove`/`restore`/`restart`) запускаются с

#### Исправлено (багфиксы code review)

- **P1.1**: `run()` отбрасывал stdout при ненулевом exit code, но инсталлер
  v5.21.0 печатает JSON и ЗАТЕМ выходит с кодом 1 для `exists`/`not_found`/
  `partial`/`rolled_back`/`repair rc=1/2`. Все status-ветки были недостижимы
  в проде (стабы `exit 0` маскировали баг). `run()` теперь всегда возвращает
  `(stdout, exit_code)`, методы парсят JSON независимо от кода выхода.
- **P1.2**: `restored.keys` десериализовался как `u32`, но инсталлер
  возвращает `"keys": true|false` (наличие `*.private`). Успешный restore
  падал на парсинге → бот сообщал о провале.
- **P2.1**: `vpnuri` в JSON-конверте — ПУТЬ к файлу, а не ссылка `vpn://`.
  `add`/`regen_client` теперь читают содержимое файла, иначе пользователь
  получал серверный путь вместо импорт-ссылки.
- **P2.2**: аварийный конверт `{"ok":false,"error":...}` при фатальной ошибке
  `check` десериализовался в фиктивный отчёт (все defaults). Теперь
  `try_error_envelope` ловит его → `ScriptFailed`.
- **P2.3**: `repair-module` использует отдельный timeout 300с (общий 60с
  обрывал DKMS rebuild + apt-установку kernel headers — заявлено до 5 минут).
- **P2.4**: endpoint-валидатор принимает порт 1..=65535 и требует парные
  скобки `[IPv6]:port` (ранее пропускал `host:0`, `host:99999`, `[host:port`).
