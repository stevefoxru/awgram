# awgram

Бот умеет подключать существующую AmneziaWG-панель (wg-easy API v14) из
карточки удалённого VPN-сервера: введите `URL | ПАРОЛЬ`, затем используйте
«Синхронизировать». Пароль хранится зашифрованным отдельным ключом. Уже
известные боту владельцы ключей сохраняются, а впервые импортированные ключи
остаются без владельца до ручного назначения.

Панель по `http://` поддерживается, но пароль передаётся по сети без TLS.
Ограничьте порт панели по IP сервера бота и по возможности включите HTTPS.

Новый VPS добавляется через пошаговый мастер в разделе серверов. После ввода
названия, IP, локации и хостера можно сразу установить AWG 1.0, подключить
существующую панель либо получить одноразовую bootstrap-команду.

Начиная с v0.26 контроллер может работать без локального VPN. Новые AWG 1.0
узлы управляются отдельным `awgram-node`: агент принимает только подписанные
команды из фиксированного списка. Модель данных уже поддерживает несколько
VPN-инстансов и драйверов на одном физическом VPS; старые узлы продолжают
работать через совместимый ограниченный SSH-мост.

Проект поддерживает исключительно AmneziaWG: AWG 1.0, AWG 2.0 и AWG-панели.
Обычный WireGuard, OpenVPN и Outline намеренно не устанавливаются и не
используются.

Telegram-бот на Rust для управления клиентами [AmneziaWG](https://amnezia.org/) прямо
с телефона: добавить/удалить клиента, посмотреть список и трафик — без SSH.

<p align="center">
  <img src="docs/media/awgram-tg.webp" alt="awgram в Telegram" width="420">
</p>

**awgram управляет нативным AmneziaWG** — kernel-модулем для Linux
(ставится [инсталлером](https://github.com/bivlked/amneziawg-installer)) —
целиком из Telegram: после установки не нужны ни консоль, ни терминал.
Нативный AWG заметно быстрее и экономнее контейнерных решений — особенно
это ощутимо на недорогих VPS.

## Возможности

### Клиенты

- ➕ **Добавление**: срок (пресеты 1д–365д или свой), PSK, защита от
  дубликатов с пересозданием; в ответ — `.conf`, QR и ссылка импорта.
- 👥 **Список**: трёхцветный статус (🟢 онлайн / 🟡 без handshake / 🔴 оффлайн)
  и время последнего handshake прямо в кнопке, трафик ↓/↑, метка ⏳ срока;
  фильтр по статусу и сортировка «онлайн вперёд»; карточка клиента,
  удаление с подтверждением; навигация по меню и страницам и кнопка 🔄
  «Обновить» редактируют сообщение на месте — без дублей.
- ⚙️ **Изменение параметров** клиента: Keepalive, DNS, AllowedIPs, Endpoint.
- 🔄 **Перевыпуск конфигов**: одного или всех сразу (опционально — со сбросом
  маршрутов).
- 📊 **Детальная статистика трафика**: сегодня / 7 дней / 30 дней, тренды,
  топ клиентов — собственное SQLite-хранилище, данные переживают ребуты.
- 📜 **История** подключений и операций по каждому клиенту.
- 🟢 **Честный онлайн-статус**: онлайн только при handshake младше 5 минут.
- 📦 **Массовая генерация** — создание до 10 клиентов за раз по префиксу
  (`user_01 … user_99`) одним действием, с продолжением существующей
  нумерации и выдачей конфигов альбомами.
- 🎛️ **Фильтр выдачи** — настройка, какие артефакты (`.conf` / QR / ссылка)
  автоматически выдаются после создания.
- 🧩 **Поартефактная выдача** — из карточки клиента можно запросить конфиг,
  QR, ссылку или всё сразу по отдельности.

### Группы и делегирование

- 🗂️ **Группы клиентов**: создание, переименование, удаление; перенос
  клиентов между группами и массовый перевыпуск конфигов группы.
- 🤝 **Делегирование**: групповые админы видят и управляют только своей
  группой; назначение — одноразовой инвайт-ссылкой (TTL 24 ч) или
  по user ID.
- 📏 **Квоты**: лимит числа клиентов на группу — действует на групповых
  админов (владелец без ограничений).

### Сервер

- 🩺 **Проверка**: карточка со статусом сервиса, интерфейса, порта, модуля,
  клиентов и фаервола (✅/⚠️/❌).
- 🔬 **Диагностика окружения**.
- 🔁 **Перезапуск сервиса** и 🛠 **починка модуля ядра** (DKMS rebuild).
- 💾 **Бэкап/восстановление** состояния AmneziaWG, скачивание архива в чат.

### Настройки и безопасность

- ⚙️ **Настройки**: язык RU/EN (у каждого админа свой), PSK по умолчанию;
  всё переживает рестарт (персистентный state).
- 🔒 **Безопасность**: доступ только для владельцев из `admin_ids` и
  назначенных ими групповых админов, вызов manage-скрипта без shell,
  секреты не попадают в логи, hardened-режим (отдельный пользователь +
  sudoers).

### Перенос бота на отдельную VPS

На действующем сервере скачайте `transfer.sh` из последнего релиза и создайте
зашифрованный архив:

```bash
curl -fsSL https://github.com/stevefoxru/awgram/releases/latest/download/transfer.sh -o /root/transfer.sh
chmod 700 /root/transfer.sh
sudo /root/transfer.sh export
```

Скопируйте `/root/awgram-transfer.enc` на чистую Ubuntu 24.04 VPS. Перед
импортом остановите только бот на старой VPS (`systemctl stop awgram`) — сам VPN
продолжит работать. Затем скачайте на новой VPS тот же скрипт и выполните:

```bash
sudo /root/transfer.sh import /root/awgram-transfer.enc
```

Импорт устанавливает бот в режиме `--controller-only`, восстанавливает данные
и проверяет SSH-связь с прежней VPS. При неудаче можно снова запустить старый
бот командой `systemctl start awgram`.
- 🚨 Мониторинг AmneziaWG каждые пять минут и аудит операций.

Основные административные операции выполняются кнопками; старые команды
сохранены только для совместимости.

## Быстрый старт

1. Получите токен бота у [@BotFather](https://t.me/BotFather) (`/newbot`)
   и свой числовой ID у [@userinfobot](https://t.me/userinfobot).
2. На VPS с установленным
   [AmneziaWG-инсталлером](https://github.com/bivlked/amneziawg-installer) выполните:

   ```bash
   curl -fsSL https://github.com/stevefoxru/awgram/releases/latest/download/install.sh | bash
   ```

3. Ответьте на вопросы установщика (язык, режим root/hardened, токен,
   ID админов) — готово: откройте бота в Telegram и нажмите `/start`.

Полностью автоматическая установка — флагами:

```bash
curl -fsSL https://github.com/stevefoxru/awgram/releases/latest/download/install.sh \
  | bash -s -- install --lang ru --mode root --token 'ТОКЕН' --admins 111111111 --yes
```

Токен можно не передавать флагом (тогда он не попадёт ни в `argv`, ни в
историю шелла) — вместо этого `export AWGRAM_TOKEN='ТОКЕН'` перед той же
командой без `--token`.

Управление после установки: `awgram-setup update | config | status | uninstall`.

Предрелизные сборки — доступны начиная с **v0.7.0**: `awgram-setup update
--channel rc` (выбор запоминается, канал rc видит и стабильные релизы;
вернуться — `awgram-setup update --channel stable`). Если на сервере
`awgram-setup` старше v0.7.0, флага `--channel` у него ещё нет — либо
выполните обычный `awgram-setup update` (он обновит и сам скрипт), либо
поставьте rc сразу однострочником из нужного релиза:

```bash
curl -fsSL https://github.com/stevefoxru/awgram/releases/download/vX.Y.Z-rc.N/install.sh \
  | bash -s -- update --channel rc
```

## Как это работает

`awgram` — один статический бинарник (Rust, `teloxide`, long polling, без
webhook), который живёт на том же VPS, что и VPN. Основные операции он
выполняет через штатный `manage_amneziawg.sh`; root-helper awgram управляет
сроком и временным отключением peer. Доступ
ограничен владельцами из `admin_ids` и назначенными ими групповыми
админами; токен и содержимое `.conf`/QR никогда не попадают в логи.

### Внутренний личный кабинет

Встроенный ЛК использует ту же SQLite-базу и запускается только после явной
настройки двух параметров в `/etc/awgram/config.toml`:

```toml
portal_bind = "127.0.0.1:8787"
portal_public_url = "https://cabinet.example.ru"
```

Исходники современного веб-интерфейса находятся в каталоге `frontend/` и
встраиваются в релизный бинарный файл при сборке. Личный кабинет и веб-админка
используют ту же базу данных, что и Telegram-бот. Вход выполняется одноразовой
ссылкой из бота; отдельные пароли пользователей не хранятся.

Для резервного входа без Telegram настройте SMTP и обязательно опубликуйте
кабинет через HTTPS:

```toml
smtp_host = "smtp.example.ru"
smtp_port = 587
smtp_username = "cabinet@example.ru"
smtp_from = "ZuevVPN <cabinet@example.ru>"
```

Пароль задаётся в `/etc/awgram/env` строкой
`AWGRAM_SMTP_PASSWORD=...`. После перезапуска пользователь может привязать и
подтвердить адрес в разделе «Поддержка». В дальнейшем вход выполняется
одноразовым шестизначным кодом, действующим 10 минут. На HTTP почтовый вход
принудительно отключён, чтобы код и сессионная cookie не передавались открыто.

Порт следует публиковать через HTTPS reverse proxy. Пользователь входит по
одноразовой ссылке из Telegram; отдельного пароля нет. Ссылка действует 15
минут и сгорает после первого открытия, сессия — 30 дней. В кабинете видны
баланс, устройства, локации, состояние серверов, трафик и последняя активность.

Оплата обычным банковским переводом остаётся ручным способом: бот показывает
заданные администратором реквизиты, принимает подтверждение и создаёт заявку.
Доступ выдаётся только после одобрения администратором. AWGram не подключается
к личному банковскому счёту и не изображает банковский эквайринг.

Партнёрская модель отделяет бренд и тариф реселлера от VPN-инфраструктуры.
Пользователь может подать заявку из нижнего меню после просмотра условий;
заявка поступает в стандартный защищённый раздел поддержки администратора.
Активные дочерние боты запускаются отдельной службой `awgram-partners`: у неё
нет административных обработчиков основного бота. Она регистрирует покупателей,
показывает розничные тарифы партнёра и создаёт заявки с зафиксированной
розничной и оптовой ценой. Администратор подтверждает оплату в карточке заказа,
выбирает рабочий AWG-сервер, после чего дочерний бот доставляет покупателю
конфигурацию, QR-код и ссылку импорта.
Покупатель видит историю и состояние своих заказов и может отменить ещё не
обработанную заявку. Владелец партнёра видит внутри дочернего бота отдельную
сводку розничного оборота, оптовой суммы и маржи без доступа к серверам.

Мастер находится в «Цены и промокоды → Партнёрские боты». Он принимает токен
нового бота отдельным сообщением, удаляет сообщение и проверяет токен через
Telegram `getMe`. Секрет записывается в `/var/lib/awgram/partner-secrets` с
правами `0600`; карточка и резервная копия SQLite токен не содержат.

Для подключения внешней платёжной страницы задайте
`acquiring_webhook_secret` (не короче 32 символов). Провайдер отправляет
`POST /api/payments/webhook` с исходным JSON:

```json
{"order_id":42,"amount_kopecks":100000,"status":"paid","transaction_id":"bank-123"}
```

Заголовок `X-Awgram-Signature` — hex-код HMAC-SHA256 от точных байтов тела.
Webhook проверяет подпись, сумму и ожидающую заявку. После подтверждения бот
уведомляет администраторов; существующий процесс выдачи выполняется из раздела
«Финансы», поэтому повтор webhook не создаёт второй ключ.

## Совместимость с инсталлером AmneziaWG

Бот — надстройка над `manage_amneziawg.sh` из
[bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer)
и напрямую зависит от его интерфейса.

Для отдельного узла AWG 1.0 создайте паспорт VPS с протоколом
`amneziawg-1`, откройте его карточку и нажмите «Установить VPN на VPS».
Первичный пароль используется только в памяти процесса; после bootstrap бот
подключается выделенным ключом с принудительно ограниченным набором команд.

Локальный сервер можно мигрировать через «Админ-панель → Серверы → Управление
VPN → Переход локального сервера на AWG 1.0». Операция требует Ubuntu 24.04,
не менее 3 ГБ свободного места и явного подтверждения `MIGRATE AWG1`. Она
создаёт backup, переживает перезагрузки и после завершения рассылает новые
конфигурации. Старые пользовательские конфигурации после перехода не работают.

- **Поддерживаемая версия инсталлера:
  [v5.25.0](https://github.com/bivlked/amneziawg-installer/releases/tag/v5.25.0)**
  (сверен `--json`-контракт). Минимальная —
  [v5.21.0](https://github.com/bivlked/amneziawg-installer/releases/tag/v5.21.0);
  более старые v5.20.x не поддерживаются — бот использует расширенный
  `--json`-интерфейс команд управления, появившийся в v5.21.0.
  v5.21.1–v5.25.0 JSON-контракт не ломали: v5.21.1/v5.21.2 — багфиксы
  валидации, v5.22.0 добавил в `regen`/`check` предупреждение о рассинхроне
  `awgsetup_cfg.init` (уходит в stderr, stdout-JSON не затронут),
  v5.23.0 — изменения только в установщике (модуль ядра на старых ядрах),
  v5.24.0 добавил аддитивное поле `module.version` в `check --json`,
  v5.25.0 — только новые предупреждения, и все они уходят в stderr.
- Используемые подкоманды: `add`, `remove`, `list`, `stats`, `regen`,
  `modify`, `backup`, `restore`, `check`, `restart`, `repair-module` —
  все с `--json`.

## Сборка из исходников

Нужен стабильный Rust не ниже 1.95 и `cargo`; TLS — на rustls, системный
`libssl` не нужен.

```bash
cargo build --release                 # target/release/awgram
./scripts/build-musl.sh [arm64|all]   # статические Linux-бинарники в dist/ (нужен Docker)
```

Релизы на тег `v*` собирают бинарники amd64+arm64 c `sha256`-суммами
автоматически.
